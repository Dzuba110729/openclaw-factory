# Learning Processor — обработка материалов

Задача — превратить большой сырой материал (транскрипт, вебинар, статью) в то, что реально применимо. Конспект, который никто не откроет, — потраченное время.

## Принцип

Обрабатываем **не в пересказ, а в применимые правила**. Разница:

| Пересказ | Применимое знание |
|----------|-------------------|
| «Спикер говорил о важности заголовков» | «Заголовок проверять вопросом "и что?" — если ответа нет, он пустой» |
| «Обсуждали структуру постов» | «Хук → проблема → механизм → решение → доказательство → призыв» |

Если из абзаца нельзя вывести действие — он в конспект не идёт.

## Порядок

1. **Прогнать целиком**, ничего не записывая. Понять, о чём вообще
2. **Выделить тезисы** — что утверждается
3. **Отсеять известное.** Оставить только новое или опровергающее имеющееся
4. **Переформулировать в правила** — в форме «когда X, делай Y»
5. **Отметить противоречия** с тем, что уже знаем
6. **Разложить по местам**

## Куда что кладётся

| Тип | Куда |
|-----|------|
| Правило работы, применимое всем | `shared/learnings/patterns.md` |
| Ошибка, которую легко повторить | `shared/learnings/anti-patterns.md` |
| Справочные факты | `knowledge/<тема>.md` воркспейса |
| Методика целиком | новый скилл — см. `skill-creator` |
| Вывод для себя | `MEMORY.md` агента |

Материал, который никуда не раскладывается, обрабатывать не стоило.

## Формат конспекта

```markdown
# <Название материала>

**Источник:** автор, дата, ссылка
**Обработан:** YYYY-MM-DD
**Вердикт:** стоило / не стоило, одной строкой

## Применимо у нас
- <правило> → куда положено

## Противоречит тому, что мы делаем
- <тезис> — разобраться, кто прав

## Отклонено
- <тезис> — почему не применимо
```

Блок «Отклонено» важен: без него через полгода кто-то принесёт ту же идею заново.

## Работа с транскриптами

- Транскрипты длинные и водянистые: полезного обычно 5–10%
- Не читать подряд — искать по ключевым словам темы
- Устная речь повторяется: один тезис проговаривается трижды. Записывать один раз
- Примеры спикера чаще всего не переносятся на нашу тематику — брать принцип, не пример

## Проверка перед применением

Прежде чем внедрять услышанное:

1. **Проверяемо ли?** Есть ли за этим данные или только уверенность спикера
2. **Наш ли контекст?** Совет для B2B-SaaS редко работает для розницы и здоровья
3. **Не противоречит ли** тому, что у нас уже проверено на практике
4. **Можно ли попробовать дёшево?** Внедрять сразу и целиком — плохая идея

Собственные проверенные данные всегда весомее чужого утверждения.
