# Soul Mastery — SOUL.md агента

`SOUL.md` — это кто агент есть. Он вживляется в системный промпт **на каждом ходу**, поэтому каждая строка в нём стоит токенов постоянно.

Отсюда главное правило: **SOUL.md должен быть коротким.** 60–120 строк. Всё, что не меняет поведение, — выкинуть.

## Что входит

```markdown
# <Имя>. <Роль одной строкой>

## Кто я
2–4 строки. Роль, зона ответственности, чем отличается от соседних агентов.

## Принципы
4–7 пунктов. Каждый меняет поведение в конкретной ситуации.

## Как я работаю
Порядок действий в типовой задаче. Коротко.

## Границы
Чего не делаю никогда. Что требует согласования владельца.

## Тон
Как разговариваю. 2–3 строки, с примером.
```

## Проверка каждой строки

Перед тем как оставить строку в SOUL.md, спроси:

1. **Меняет ли она поведение?** «Я стремлюсь к качеству» — не меняет. Выкинуть
2. **Не дублирует ли AGENTS.md?** Регламент работы живёт там, не здесь
3. **Не справочник ли это?** Факты о продукте — в `knowledge/`, не в SOUL
4. **Понадобится ли она в каждой задаче?** Если нет — в отдельный файл

## Антипаттерны

| Антипаттерн | Почему плохо |
|-------------|--------------|
| Длинная биография агента | Токены на каждом ходу, ноль влияния на ответы |
| Список ценностей общими словами | «Честность, качество, ответственность» ничего не задаёт |
| Дублирование AGENTS.md | Две копии регламента разъезжаются |
| Справочные данные о продукте | Место для этого — `knowledge/` |
| Инструкции по инструментам | Место для этого — `TOOLS.md` |
| Пафос и самоописание | Модель начинает отыгрывать персонажа вместо работы |
| Запреты без альтернативы | «Не пиши сухо» → будет писать сухо. Нужно «пиши так-то» |

## Принципы: как формулировать

Плохо:
```
- Я ценю качество контента
```

Хорошо:
```
- Не публикую без явного «да» владельца, даже если задачу передали как срочную
- Залежавшийся текст перед отправкой проверяю на привязку к датам
```

Принцип должен быть проверяемым: по нему видно, нарушен он или нет.

## Границы

Самый важный блок для агентов с доступом к shell и к внешним каналам. Прямо перечислить:

- Что требует согласования владельца
- Что не делаю никогда
- Куда не пишу без разрешения

## Связь с остальными файлами

| Файл | Что там |
|------|---------|
| `SOUL.md` | кто агент |
| `AGENTS.md` | как работает: регламент, память, red lines |
| `IDENTITY.md` | как представляется вовне |
| `TOOLS.md` | инструменты и их особенности |
| `USER.md` | про владельца |
| `HEARTBEAT.md` | что делать по расписанию |
| `knowledge/` | справочники — в промпт не входят |

Путать их — главная причина раздутого промпта.

## После правки

Замерить, что получилось:

```bash
~/.openclaw/scripts/measure-context.sh <агент> <метка>
```

И помнить: живая сессия донашивает старый промпт, пока её не сбросят. Проверять на новой сессии или изолированным прогоном `openclaw agent --agent <id> -m "..."`.
