# Agent Memory — как агенту помнить

Каждая сессия начинается с нуля. Помнит только то, что записано в файлы.

Правило одно: **мысленных заметок не существует.** Решил запомнить — записал в файл.

## Три слоя

| Слой | Файл | Что туда | Срок жизни |
|------|------|----------|-----------|
| Оперативный | `memory/active-context.md` | На чём остановились, что в работе прямо сейчас | Переписывается |
| Дневник | `memory/YYYY-MM-DD.md` | Сырой лог дня: что делали, что решили, что сломалось | Навсегда |
| Долговременная | `MEMORY.md` | Выжимка: решения, правила, выводы | Навсегда |

Плюс `knowledge/` — справочные материалы: бренд, продукты, регламенты. Это не память, это база знаний, она меняется редко.

## Что писать в дневник

Каждый рабочий заход:

- Что сделано, с результатом
- Какие решения приняты и почему
- Что не получилось и почему — это ценнее успехов
- Что просил владелец, его формулировками
- Открытые хвосты

Не писать: пересказ собственных сообщений, содержимое файлов, которые и так на диске.

## Что попадает в MEMORY.md

Только то, что пригодится через месяц:

- Правила и регламенты («публикация только после явного "да"»)
- Устойчивые предпочтения владельца
- Решения с обоснованием — чтобы не переоткрывать спор
- Выводы из ошибок

Не попадает: разовые задачи, текущий статус, то, что выводится из файлов проекта.

Раз в неделю-две перечитывай дневники и переноси стоящее в `MEMORY.md`.

## Безопасность

`MEMORY.md` грузится **только в основной сессии** — в личных чатах с владельцем.

В групповых чатах и при работе с посторонними — не загружать: там личный контекст, который не должен утечь к чужим людям.

## Поиск вместо чтения

Не читай файлы памяти подряд — это раздувает контекст. Ищи:

```bash
openclaw memory search "запрос" --agent <id>
openclaw memory status          # состояние индекса
```

Поиск семантический, по эмбеддингам. Индекс обновляется по расписанию (launchd `ai.openclaw.reindex`, 4:30). Если поиск отдаёт устаревшее — `openclaw memory index`.

## Начало сессии

Файлы воркспейса (`SOUL.md`, `AGENTS.md`, `USER.md`, `TOOLS.md`, `IDENTITY.md`, `MEMORY.md`, `HEARTBEAT.md`) **уже вживлены в системный промпт**. Читать их инструментом повторно — трата токенов впустую.

Подтянуть стоит только:

1. `memory/active-context.md`
2. Сегодняшний `memory/YYYY-MM-DD.md`, если есть
3. По конкретному вопросу — поиск, а не чтение подряд

## Гигиена

- Дневники старше полугода — в `memory-archive/`, из индекса они уходят
- `active-context.md` держать коротким: 20–30 строк. Это доска задач, а не летопись
- Не дублировать одно и то же в трёх слоях
- Противоречие между старой и новой записью — исправлять старую, а не копить обе
