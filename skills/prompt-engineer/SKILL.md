# Prompt Engineer — промпты, которые работают

Плохой ответ модели почти всегда означает плохо поставленную задачу, а не слабую модель.

## Структура промпта

```
1. Роль и контекст  — кто отвечает и в какой ситуации
2. Задача           — что нужно сделать, одним предложением
3. Входные данные   — материал, с которым работать
4. Ограничения      — чего нельзя, формат, объём
5. Формат ответа    — как именно должен выглядеть результат
6. Примеры          — 1–3 образца, если формат нетривиален
```

Порядок важен: инструкции до данных работают надёжнее, чем после.

## Что даёт наибольший прирост

| Приём | Когда применять |
|-------|-----------------|
| **Конкретный формат вывода** | Всегда. «Ответь тремя строками» лучше, чем надежда |
| **Примеры (few-shot)** | Формат нестандартный или стиль важен |
| **Явные запреты** | Модель регулярно делает лишнее |
| **Разбить на шаги** | Задача составная |
| **Дать критерий качества** | Есть понятие «хорошо» и «плохо» |

## Частые ошибки

| Ошибка | Симптом | Исправление |
|--------|---------|-------------|
| Несколько задач в одном промпте | Часть задач проигнорирована | Разбить на вызовы |
| Отрицания без альтернативы | Делает ровно запрещённое | Сказать, что делать вместо |
| Нет формата вывода | Каждый раз по-разному | Задать формат явно |
| Размытые оценки («хорошо», «креативно») | Средний результат | Дать критерий |
| Данные перед инструкцией | Инструкция теряется | Инструкция сверху |
| Слишком вежливо и обтекаемо | Модель «обсуждает» вместо работы | Прямая формулировка задачи |

## Отладка

Ответ не тот — по порядку:

1. **Сузить.** Убрать всё лишнее, оставить одну задачу. Воспроизводится?
2. **Добавить пример** правильного ответа
3. **Задать формат** жёстче
4. **Проверить противоречия** — нет ли в промпте двух несовместимых требований
5. **Проверить входные данные** — часто проблема в них, а не в промпте

Менять по одному элементу за раз, иначе непонятно, что помогло.

## Промпты для агентов OpenClaw

Отличаются от разовых запросов: живут в системном промпте и стоят токенов **на каждом ходу**.

- Каждая строка бутстрапа умножается на число ходов — лишнее выкидывать
- Инструкции, которые агент и так выполняет, убирать
- Разовое — в сообщение, постоянное — в файлы воркспейса
- Проверять размер: `~/.openclaw/scripts/measure-context.sh <агент> <метка>`
- Точная разбивка: `openclaw agent --json` → `result.meta.systemPromptReport`

Отладка агента без отправки наружу:

```bash
openclaw agent --agent <id> -m "задача"    # без --deliver никуда не уходит
```

## Проверка промпта

- [ ] Одна задача
- [ ] Формат ответа задан явно
- [ ] Нет противоречивых требований
- [ ] Ограничения сформулированы как «делай X», а не только «не делай Y»
- [ ] Есть критерий, по которому результат можно принять или отклонить
- [ ] Проверен на 2–3 разных входных данных, а не на одном удобном
