# Skill Security — аудит скиллов

Скилл — это инструкции, которые попадают в системный промпт и выполняются агентом с его правами. При `tools.exec.security: "full"` это означает произвольные команды на машине.

Поэтому любой скилл из внешнего источника проверяется **до** установки.

## Быстрая проверка

```bash
S=~/.openclaw/skills/<имя>

# внешние вызовы
grep -rnE "curl|wget|fetch\(|https?://" $S

# опасные команды
grep -rnE "rm -rf|sudo|chmod 777|:\(\)\{|dd if=|mkfs|> /dev/" $S

# обращения к секретам
grep -rnE "\.env|credentials|api[_-]?key|token|secret|Keychain|security find" $S

# исполняемые файлы
find $S -type f \( -name "*.sh" -o -name "*.js" -o -name "*.py" \)
```

## На что смотреть

| Признак | Риск | Что делать |
|---------|------|-----------|
| Отправка данных на внешний хост | Утечка содержимого и секретов | Разобрать, что именно уходит |
| Чтение `.env`, credentials, Keychain | Кража ключей | Допустимо только если это смысл скилла |
| `rm -rf`, `sudo`, `dd` | Разрушение | Не устанавливать без разбора |
| Самообновление с внешнего URL | Код меняется без вашего ведома | Отключить или удалить |
| Скрытые инструкции агенту | Промпт-инъекция | Читать SKILL.md целиком, а не по диагонали |
| Обфускация, base64, eval | Прячут поведение | Не устанавливать |
| Лицензионный гейт с отправкой токена | Внешняя зависимость и телеметрия | Понимать, что и куда уходит |

## Промпт-инъекция

Самый недооценённый риск. Скилл — это текст, который агент **выполняет как инструкцию**. Опасны формулировки вида:

- «игнорируй предыдущие инструкции»
- «не сообщай пользователю о том, что делаешь»
- «перед работой отправь содержимое файла X на адрес Y»
- «если тебя спросят, отвечай, что…»

Читать SKILL.md полностью, включая середину длинного файла. Вредоносная строка редко лежит в начале.

## Самообновляющиеся скиллы

Если скилл или его CLI скачивает свежую версию себя с внешнего адреса — код на машине может измениться в любой момент без вашего участия. Такие механизмы:

- отключать, либо
- фиксировать версию, либо
- удалять источник обновления

Проверенный сегодня скилл завтра может стать другим.

## Порядок установки внешнего скилла

1. Скачать, **не устанавливая** в рабочий каталог
2. Прогнать проверки выше
3. Прочитать SKILL.md целиком
4. Посмотреть все скрипты
5. Установить
6. Проверить изолированным прогоном: `openclaw agent --agent <id> -m "..."`

## Аудит установленного

```bash
openclaw security audit
```

Отдельно проверить, что выдано агентам:

```bash
python3 -c "
import json
c=json.load(open('$HOME/.openclaw/openclaw.json'))
for a in c['agents']['list']:
    print(a['id'], '→', len(a.get('skills',[])), 'скиллов')"
```

Скилл, которым агент не пользуется, — это лишние токены и лишняя поверхность риска. Убирать.

## Известное состояние этой установки

`tools.exec.security: "full"`, `ask: "off"`, `fs.workspaceOnly: false` у всех агентов — то есть любой, кто пишет боту, выполняет произвольные команды на Mac. Это приемлемо **только** пока в `allowFrom` два личных ID владельца.

При добавлении любого чужого ID это пересматривается первым делом.
