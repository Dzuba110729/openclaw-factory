# Agent Architect — проектирование агентов

Прежде чем создавать агента, ответь на вопрос: **а нужен ли отдельный агент?**

Отдельный агент оправдан, когда у задачи своя память, свой канал связи и своя зона ответственности. Если нужен просто другой стиль ответа — это скилл, а не агент. Каждый агент стоит токенов на бутстрапе и требует обслуживания.

## Проектирование: шесть вопросов

1. **Зона ответственности.** За что отвечает и за что не отвечает
2. **Границы с соседями.** Где заканчивается он и начинается другой агент. Пересечения — источник дублирующей работы
3. **Вход.** Откуда приходят задачи: владелец, другой агент, расписание, событие
4. **Выход.** Что производит. Куда кладёт результат
5. **Что решает сам, а что несёт на согласование**
6. **Чем меряется, что он работает**

Без ответа на пятый вопрос агент либо парализован, либо опасен.

## Создание

```bash
openclaw agents create <id>
```

Дальше руками:

1. **Воркспейс** `~/openclaw-factory/agents/<id>/`:
   - `SOUL.md` — кто он (скилл `soul-mastery`)
   - `AGENTS.md` — регламент работы, память, red lines
   - `IDENTITY.md` — как представляется
   - `TOOLS.md` — инструменты и их особенности
   - `USER.md` — про владельца
   - `MEMORY.md` + `memory/` — память (скилл `agent-memory`)
   - `knowledge/` — справочники

2. **Allowlist скиллов** в `~/.openclaw/openclaw.json`:

```json
{ "id": "<id>", "skills": ["telegram", "memory-system", "agent-memory"] }
```

Явный список **заменяет** `agents.defaults.skills`, а не дополняет. Давать только то, что реально нужно: блок скиллов — крупнейшая часть системного промпта.

3. **Канал.** Telegram-аккаунт в `channels.telegram.accounts.<id>`, с `allowFrom` и `groupAllowFrom`.

4. **Проверка:**

```bash
openclaw status
openclaw agent --agent <id> -m "ответь: ок"
```

## Безопасность при создании

- `allowFrom` — только доверенные ID. При `tools.exec.security: "full"` любой, кто пишет боту, выполняет команды на машине
- Новому агенту не выдавать shell, если задача его не требует
- В группах бот должен отвечать только на упоминание

## Типовые роли

| Роль | Признак, что нужна отдельно |
|------|------------------------------|
| Координатор | Задачи приходят от людей и раздаются агентам |
| Производитель контента | Своя память по площадке и свой регламент публикации |
| Дизайнер | Свои ключи к сервисам генерации |
| Технический | Обслуживание системы, shell |
| Архивариус | Долговременная память, обработка знаний |

## Частые ошибки

- **Агент без границ.** «Помогает со всем» — не будет делать ничего хорошо
- **Дублирование ролей.** Два агента с пересекающейся зоной начинают делать одну работу дважды
- **Раздутый бутстрап.** Справочники в промпте вместо `knowledge/`
- **Все скиллы всем.** Промпт растёт, качество падает
- **Нет BOOTSTRAP.md** — агент не проходит первичную настройку и не понимает, кто он
- **Shell там, где не нужен** — лишний риск без выгоды

## После создания

Замерить промпт: `~/.openclaw/scripts/measure-context.sh <id> baseline`.

Через неделю посмотреть, что агент реально делает, и урезать то, чем он не пользуется.
